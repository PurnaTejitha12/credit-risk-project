Checkpoint 2 — Baseline Report
1. Objective

The objective of Checkpoint 2 is to build a complete data ingestion and preprocessing pipeline, train a baseline intent-classification model, establish an evaluation benchmark, and document the baseline results.

2. Dataset

The dataset contains customer-support text messages with their corresponding intent labels and confidence values.

The dataset contains the following fields:

Field	Description
text	Customer utterance
intent	Target intent category
confidence	Confidence associated with the example

The current dataset contains two intent classes:

order_status
return_request
3. Data Ingestion

The pipeline reads the raw tab-separated dataset using pandas.

During ingestion, the pipeline verifies that the required columns exist:

text
intent
confidence

The pipeline also removes duplicate records and records with missing text or intent values.

4. Preprocessing

The following preprocessing steps are applied:

Convert text to string.
Remove leading and trailing whitespace.
Convert text to lowercase.
Normalize repeated whitespace.
Remove empty text records.
Convert the confidence field to numeric format.

The cleaned dataset is saved as:

outputs/processed_dataset.csv

5. Train/Test Split

The dataset is divided into training and testing subsets.

A fixed random seed of 42 is used so that the experiment is reproducible.

Stratified sampling is used to preserve the intent distribution between the training and testing sets.

6. Baseline Model

The baseline model uses:

TF-IDF

TF-IDF converts customer messages into numerical feature vectors.

Both unigrams and bigrams are used:

ngram_range=(1, 2)

Logistic Regression

Logistic Regression is used as the baseline classifier.

This provides a simple and interpretable benchmark against which future models can be compared.

7. Evaluation Metrics

The baseline is evaluated using:

Accuracy
Precision
Recall
F1 score
Classification report
Confusion matrix

The primary benchmark metric is weighted F1 score, while accuracy is also reported.

8. Benchmark

After running the pipeline, the benchmark results are stored in:

outputs/benchmark.csv

The benchmark contains:

Metric	Score
Accuracy	Generated by pipeline
Weighted Precision	Generated by pipeline
Weighted Recall	Generated by pipeline
Weighted F1	Generated by pipeline
9. Model Artifact

The trained baseline model is saved to:

outputs/baseline_model.joblib

This model can be loaded later for inference without retraining.

10. Error Analysis

The confusion matrix is generated to identify incorrect predictions between the two intent classes.

Because the current dataset is very small, individual test examples can have a large effect on the reported metrics.

Therefore, the baseline scores should be considered an initial benchmark rather than a reliable estimate of production performance.

11. Limitations

The current dataset contains only a small number of examples.

This creates several limitations:

The test set is very small.
Performance metrics may have high variance.
The model may not generalize to unseen customer language.
Two intents may not represent the complete production intent space.
More training examples are required for a robust model.
12. Checkpoint 2 Conclusion

The complete baseline pipeline has been implemented.

The pipeline performs:

Raw data → Validation → Cleaning → Preprocessing → Train/Test Split → TF-IDF → Logistic Regression → Evaluation → Benchmark → Saved Model

The resulting benchmark will serve as the reference point for future model improvements.
